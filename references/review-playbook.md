# 审查手册

解析给的是**事实**，审查给的是**判断**。判断必须可回溯到解析产物或外部权威文档，
两者都拿不到就写"需核实"。

## 一、分级

| 级别 | 定义 | 例子 |
|---|---|---|
| 🔴 P0 致命 | 板子做出来不工作，或上电即损坏 | 电源极性与封装反、地址选通脚悬空、稳压器反馈接错、器件耐压不足 |
| 🟠 P1 严重 | 能工作但不可靠 / 有隐患 / 装不上 | 封装与料号不符、去耦不足、采样电阻位置错、丝印值与实物不符 |
| 🟡 P2 建议 | 优化项，不影响功能 | 丝印可读性、测试点缺失、走线绕远、安装孔缺失 |

**单证据源不得直接下 P0。** 至少两条独立证据（工程记录 + 官方手册 / 官方库），
否则降级为"需核实"。

## 二、引脚核对（最容易抓 P0 的一步）

顺序固定：

1. **物理引脚号 = 封装焊盘号**（`PAD.num`）。先用焊盘坐标验证封装编号方向
   （标准 SOP/QFN 为 1 脚左上、逆时针）；
2. **符号引脚号 ≠ 物理引脚号**。把工程符号引脚表逐脚对官方数据手册；
3. **官方手册优先，记忆不算证据**。同一器件凭记忆判断引脚功能已经失败过多次，
   而且方向相反（先说"整体错位"，后来发现其实是标准封装）。

### 官方手册怎么读

- 厂商 datasheet 的引脚表**常以图片渲染**，直接抓文字抓不到；优先找带文本层的 PDF；
- PDF 文本层里，引脚名经常**比引脚号高约一个行距**。按"最近 y"配对会整体错行，
  把 13/14 两脚判成互换——这是真实踩过的坑；
- 所以：矢量文本坐标只作辅助。结论必须用**渲染后的整页图**（截图 / OCR）复核；
- 无图可用、偏移规律不成立时，标"需核实"，不下结论；
- 若已出过错误结论，报告里显式更正，不要悄悄改。

### "不使用某引脚" ≠ "可以悬空"

需求写"不使用 S3"时，它翻译成硬件约束是**该脚硬接 GND 或 VCC**，
不是留空、也不是打 NO_CONNECT 标记。DRC 对此完全无感。

核对时并列三份来源，冲突就交用户确认，不擅自选边：

| 来源 | 内容 |
|---|---|
| 需求文档原文 | 通道数、地址线接法 |
| 用户口述 | 常有"按位号习惯"的说法 |
| 工程实际 | 位号 + 焊盘 + 网络 |

## 三、封装与 BOM

### 三方对齐

工程符号/封装 ↔ 立创官方库 ↔ BOM 行。任一侧缺失都要在报告里写明。

1. **位号集合先对齐**：BOM 全部 Designator 展开成集合，与工程 Designator 求差。
   多一颗、少一颗都是采购风险，单列 P1；
2. **封装看官方库，不靠记忆**：`https://easyeda.com/api/products/<供货编号>/components`
   返回里 `result.dataStr.head.c_para.package` 是封装名，
   `result.dataStr.shape[]` 里的 `P~show~0~<脚号>~...~<脚名>` 是符号引脚表，
   `result.packageDetail.dataStr.shape[]` 里的 `PAD~...` 是焊盘几何；
3. **封装名不同 → P0/P1（贴不上）**；封装名相同但引脚名不同 → 逐脚列差异；
4. 丝印标称值必须等于 BOM 的 Value / MPN。

BOM 读法：`openpyxl` 读 xlsx，常见列
`No. / Quantity / Comment / Designator / Footprint / Value / Manufacturer Part / Supplier Part`。

## 四、结构性检查

按本次工程的实际数据推导检查项，不套用别的板子：

- **电源**：输入保护、反接保护、稳压器反馈分压、输出电容、上电时序；
- **地**：AGND / DGND / PGND 是否在原理图上独立、单点连接位置是否合理；
  多个地在 PCB 上被合成一个网络而原理图没合并 → 明确列出；
- **去耦**：每个电源脚是否有就近电容，容值组合是否覆盖低频与高频；
- **时钟/高速**：走线是否跨分割、参考平面是否连续、终端匹配；
- **接口**：ESD、限流、电平匹配、连接器引脚定义与线序；
- **可制造**：最小线宽/间距、阻焊桥、过孔盖油、拼板工艺边、Mark 点。

## 五、网络名与丝印的一致性

- 网络名拼写（`MEASSURE` / `MEASURE`、`LOW_BATTARY`）——拼错不影响电气，但会误导后来人；
- 丝印功能标签与信号是否对应（丝印写 `SWO` 但工程里没有这个网络）；
- 死网络：定义了但没有任何引脚连接的网络，建议删除。

这些多为 🟡，但"标签与信号不符"在调试阶段代价很高，可以升 🟠。

## 六、图片与 OCR

模型不能读图时，预览图（webp）无法使用，改用元素几何数据——几何比图更可靠，
不要声称"看过图"。

必须看图时（例如核对引脚配置图）：

1. 先判断载体：矢量文本 + 路径线 → 直接用位置化文本提取；
   位图 XObject → 按 `/Filter` 识别（`DCTDecode` 存 jpg，`FlateDecode` + `DeviceRGB` 存 png）；
2. 无视觉模型时可用 Windows 内置 OCR（离线，需 Windows PowerShell 5.1 调 WinRT）；
3. 把图**放大 3 倍**再 OCR，小字号识别率明显提升；
4. 图面排版瑕疵（某个名称偏移一行）不能推翻编号证据，以"脚号列 + 图编号 + 表列描述"
   三处交叉为准，并在报告里说明瑕疵位置。

## 七、报告纪律

- 每条问题四要素：📍位置（位号/网络/引脚）· 🔍当前状态 · 💣影响（带计算或手册依据）
· 🛠建议。再加 🧾记录证据（ticket / 焊盘号）；
- 附 ✅设计亮点、📖关键参数验算、⚠️数据缺失清单；
- 结尾给修复优先级和明确判定：**可打样 / 需修改 / 无法判定**；
- 不写"整体已审查""基本没有问题"这类概括结论。没查的项必须列出来；
- 数字必须能在产物 JSON/CSV 里查到，不能只在报告里出现。

## 八、何时停止

- 关键器件型号或封装无法确认，且用户也提供不了 → 只列已确认项，其余标"需核实"；
- 引脚核对证据冲突（手册与官方库不一致）→ 停下来说明冲突，不选边；
- 工程文件本身损坏 / 版本不支持 → 停止解析，说明原因，不要产出半成品报告。
